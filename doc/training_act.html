训练 ACT 策略 ── RoboCasa OpenCabinet 开柜子任务

2026-05-29 · Linus 模式 · robocasa-training 仓库训练流水线总览

TL;DR：在本仓里跑 ACT (Action Chunking Transformer) 训 RoboCasa OpenCabinet。路径：用 robocasa 演示生成器在 ~/.cache/robocasa 录 200-500 条 HDF5 演示 → 转 LeRobot dataset → LeRobot trainer 跑 ACT（chunk=100, batch=8, lr=1e-5）→ 接 ZMQ 推理 server 复用现有 RoboCasa 评估流水线（同 GR00T 客户端代码路径）。单 H800 ¥9/h × 12 h ≈ ¥108 / 任务，先开柜子，跑通后再扩到 18 atomic 任务。
Train ACT on RoboCasa OpenCabinet: collect 200-500 HDF5 demos via robocasa's generator → convert to LeRobot format → train ACT (chunk=100, bs=8, lr=1e-5) via LeRobot → wrap with a ZMQ server reusing the existing RoboCasa eval client. ~¥108/task on a single H800 (12 h). Start with cabinet open, then scale to all 18 atomic tasks.

1. 为什么是 ACT (Why ACT)

策略规模训练成本OpenCabinet 适配度本仓定位
ACT (Action Chunking Transformer) ~80 M 参数 单 GPU · 半天 视觉 + 关节状态原生输入；chunk 输出抗抖动 本仓默认 baseline
Diffusion Policy ~250 M 单 GPU · 1-2 天 对长程任务好，对 OpenCabinet 略奢侈 下一阶段对比组
GR00T N1.5 / pi0.5 2-3 B (VLA) 多 GPU · 数天 泛化好，但成本与本仓单任务目标不匹配 评估端复用官方 ckpt（见 RoboCasa.ipynb）
SmolVLA ~450 M 单 GPU · 1 天 VLA 小型化，需 lerobot dataset 对照训练组
Linus 判断：单任务 200 演示，ACT 80 M 是品味正确的选项 — 比 diffusion policy 简单、比 VLA 便宜、推理端只输出动作 chunk，直接复用 scripts/_gr00t_eval_client.py 的 ZMQ + action-chunk replay 协议，零修改。Reuses the existing GR00T eval client wire format verbatim — no special-casing.

3. 数据规格 (Data Schema)

3.1 RoboCasa 原始演示 (HDF5)

字段形状说明
obs/robot0_agentview_left_image(T, H, W, 3) uint8左 agentview RGB · 256×256 · 20 Hz
obs/robot0_agentview_right_image(T, H, W, 3) uint8右 agentview RGB
obs/robot0_eye_in_hand_image(T, H, W, 3) uint8腕部相机 RGB（夹爪同步）
obs/robot0_eef_pos(T, 3)末端位姿（世界系）
obs/robot0_eef_quat(T, 4)末端四元数
obs/robot0_gripper_qpos(T, 2)夹爪两指 qpos
obs/robot0_base_pos(T, 3)底盘位姿（OmronPanda 全向）
actions(T, 12)delta arm 6 + gripper 1 + base 3 + mode 2
动作 12 维拆解和 GR00T 一致（action.eef_position 3 + action.eef_rotation 3 + action.gripper 1 + action.base_motion 3 + action.control_mode 2）。Action layout matches GR00T's modality config, so eval client needs no change.

3.2 LeRobot 数据集格式

features = {
    "observation.images.agentview_left":  Image(shape=(256,256,3)),
    "observation.images.agentview_right": Image(shape=(256,256,3)),
    "observation.images.eye_in_hand":     Image(shape=(256,256,3)),
    "observation.state":                  Sequence(Value("float32"), length=16),
    "action":                             Sequence(Value("float32"), length=12),
}
fps = 20

observation.state 16 维 = eef_pos 3 + eef_quat 4 + gripper_qpos 2 + base_pos 3 + base_quat 4（与 GR00T panda_omron 数据配置对齐）。

4. 训练超参 (Hyperparameters)

项值原因 / 来源

batch size8H800 80 G 可塞下 chunk=100 + 3 cam 256² fp32 backbone
learning rate1e-5（transformer）
1e-4（视觉 encoder）		LeRobot ACT 默认；视觉 encoder 不冻结但 lr 高 10×
optimizerAdamW(β=0.9,0.95, wd=1e-4)ACT 原作 + LeRobot
KL weight10CVAE prior 正则；过低 → mode collapse
vision backboneResNet18 (ImageNet pretrain)原作；80 M 总参数主要在 transformer，不在 backbone
training steps100k (~600 epoch × 200 demos)OpenCabinet 单任务收敛阈值
num demos200-500RoboCasa 官方 atomic 任务推荐量级
temporal ensembling开（推理时）多个 overlap chunk 加权平均，抑制不连续

7. 落地步骤 (Step-by-Step)

步骤 1 ── 采演示（在 robocasa conda env）

python scripts/collect_demos.py \
    --task OpenCabinet \
    --n-demos 300 \
    --output ~/.cache/robocasa/demos/opencab_v1.hdf5
# 单机录 300 条，约 30 min（CPU + 离屏 mujoco render）。

步骤 2 ── 转 LeRobot

python scripts/convert_hdf5_to_lerobot.py \
    --hdf5 ~/.cache/robocasa/demos/opencab_v1.hdf5 \
    --repo-id local/robocasa_opencab_act \
    --fps 20

步骤 3 ── 训 ACT（在 lerobot conda env）

python scripts/train_act.py \
    --dataset local/robocasa_opencab_act \
    --output-dir checkpoints/act_opencabinet \
    --steps 100000 \
    --batch 8 \
    --chunk 100

步骤 4 ── 评估（接现有 RoboCasa 评估流水线）

# 父仓 mujoco-experience/scripts/robocasa_eval_act.py 是一个薄包装：
#   - server: bash -c "conda activate lerobot && python robocasa-training/scripts/serve_act.py ..."
#   - client: 复用 scripts/_gr00t_eval_client.py（同 ZMQ 协议）
python scripts/robocasa_eval_act.py \
    --env-name OpenCabinet \
    --n-episodes 50 \
    --ckpt robocasa-training/checkpoints/act_opencabinet \
    --render
Linus 提醒：评估端不要写新协议。ACT 推理就是 obs → action chunk (T,12)，和 GR00T 的输出形状一致 — 客户端代码完全复用，这是品味，不是巧合。Same wire shape → reuse the client. Not a coincidence, that's the point.

10. 三问自检 (Linus Three Questions)

  • 真问题还是假想？ ✅ 真：RoboCasa GR00T 评估流水线已通，需要本地可训的策略对比组，ACT 是最小可行选项。
  • 有更简单方案吗？ ❌ 没有 — 比 ACT 更简单的（BC-RNN）在 RoboCasa 上 SR 低于 30%，对比意义弱；更复杂的（diffusion / VLA）训练成本高 5-10×。
  • 会破坏什么吗？ ❌ 不会 — 评估端协议 100% 复用 GR00T 客户端；父仓 mujoco-experience 仅新增一个薄 orchestrator 脚本，不动现有评估代码。
结论：值得做。先把 OpenCabinet 单任务跑通，剩下的全是数据规模和任务数量的横向扩展，没有结构性新工作。Worth doing. Single-task OpenCabinet first; everything else is horizontal scaling.
