📌 实验结果小结 / Results summary (2026-06-02 更新 · 训练已停)

结论：跑完到 step 12550/15000 后停训。SR 全程 0%，瓶颈是数据量（human-500 太少），不是欠训、不是坐标 bug。下一步 = MimicGen 10× 扩数据再训，而非继续堆步数。

Stopped at step 12550/15000. Success rate stayed 0% across every checkpoint. Loss fell normally but SR never moved; motion plateaued by step 5000; giving 3× time just made the arm wander instead of converging on the handle; changing the cabinet (seed) changed behaviour but none solved the task. Root cause is data quantity (500 human demos is too few), not undertraining and not a coordinate bug — the decisive control is that ACT on the same task with the same human-500 is also 0% (a known data ceiling). Next step: scale data with MimicGen 10×, not more steps.

1. DreamZero 是什么，值不值得这么干 (What & Is it worth it?)

DreamZero（project · arXiv 2602.15922 · GitHub）不是 VLA，是 World-Action Model (WAM)：在预训练 视频扩散骨干（Wan2.1-I2V-14B-480P）上联合预测「未来世界状态（视频）+ 动作」。卖点是 用视频当稠密监督，少样本就能泛化到新任务/新本体（论文宣称 vs SOTA VLA 泛化 2×，10–20 min 视频即可 +40%）。

Linus 三问判断
真问题还是假想？真问题：我们要的不是「再榨 OpenCabinet 几个点」，而是验证 WAM 范式在 RoboCasa sim 上是否 work。GR00T N1.5 已 64%，DreamZero 是来回答「视频世界模型路线能不能迁过来」的研究性实验。
有更简单方案吗？有，但目标不同。要刷 SR 就继续 GR00T（已有 50–64%）。要探 WAM，DreamZero 是当前最现成的开源 14B WAM，且我们已有 LeIsaac 跑通的脚手架——边际成本极低。
会破坏什么吗？零破坏。独立 conda env、独立 repo（dreamzero-repo）、独立 AutoDL 实例、独立产物目录。不碰榜单、不碰本机 GR00T 训练。
核心结论 / Verdict：✅ 值得跑一次。理由不是「会更强」（14B 视频扩散打一个窄 sim 任务，是用牛刀），而是脚手架已就绪 + RoboCasa 数据天然契合 DreamZero（3 视角 + h264），一次 ~3–4 h 的 LoRA 就能拿到 WAM 在 RoboCasa 的首个数据点。期望值：能否在 500 demo 下接近 GR00T 区间（>50%），是这次实验的 success metric。

4. 维度映射设计 (Dim mapping — the one real design decision)

从数据集 meta/modality.json 读出的真实切分（已确认）：

state[16]区间action[12]区间relative?
base_position[0,3]base_motion[0,4]需验证
base_rotation[3,7]control_mode[4,5]否（离散）
eef_position_relative[7,10]end_effector_position[5,8]需验证
eef_rotation_relative[10,14]end_effector_rotation[8,11]需验证
gripper_qpos[14,16]gripper_close[11,12]否（二值）
唯一需要验证的设计点：relative-action 选择。RoboCasa OSC 控制器的 end_effector_position/rotation 本身可能已是 delta 指令。DreamZero 的 --relative-action-keys 是「相对 chunk 首帧」的再归一化——若 action 已是 delta，再标 relative 可能双重差分。
How to apply：首跑先不标 eef 为 relative（当绝对量 + q99 归一化，与 GR00T N1.7 处理一致），smoke 50 step 看 loss；若 loss 异常或 eval 全 0 再切相对量对比。control_mode / gripper_close 永远不标 relative。

4.1 GEAR 转换命令（RoboCasa 版）

# 仅写 meta/，不改 parquet/video，~1 min。先备份原 modality.json
DS=~/.cache/robocasa/datasets/v1.0/target/atomic/OpenCabinet/20250813/lerobot_old
python $DREAMZERO_REPO/scripts/data/convert_lerobot_to_gear.py \
    --dataset-path "$DS" \
    --embodiment-tag robocasa \
    --state-keys  '{"base_pos":[0,3],"base_rot":[3,7],"eef_pos":[7,10],"eef_rot":[10,14],"gripper_qpos":[14,16]}' \
    --action-keys '{"base_motion":[0,4],"ctrl_mode":[4,5],"eef_pos":[5,8],"eef_rot":[8,11],"gripper_close":[11,12]}' \
    --relative-action-keys base_motion \
    --task-key task \
    --force
# ↑ 首跑只把 base_motion 当相对（移动底盘累积位移）；eef 先当绝对量。loss 不对再调。

5. 硬件与显存：为什么必须上 AutoDL (Hardware reality)

卡训练？说明
本机 4090 24G✗ 训不动14B Wan + UMT5-XXL bf16 权重就远超 24G。仅能做 NF4 量化推理（LeIsaac inference/dreamzero/wan14b_nf4_forward.py 已验证）。
48G（A6000 / L20）⚠ 高风险bf16 LoRA + ZeRO-2 offload 勉强，33 帧 × 320×176 激活 + VAE 容易 OOM。不推荐首跑。
A100 80G / H100 80G✓ 推荐bf16 LoRA r=4 + ZeRO-2 offload 舒适。AutoDL 主力选项。
RTX Pro 6000 96G✓ 最佳LeIsaac 实测目标卡：r=32 峰值 ~58G，r=4 更省，单卡无需 DeepSpeed。
实测要点（来自 LeIsaac recipe 注释）：
  • 放弃 INT8/bnb 路线 ── DreamZero 源码无 bnb hooks，patch 成本 > 升级 GPU 成本。直接 bf16 LoRA。
  • PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True 降碎片（近满显存必加）。
  • Blackwell（Pro 6000 sm_120）多卡：NCCL_P2P_DISABLE=1 + 预载 NCCL 2.30+，否则 illegal memory access。单卡可忽略。
  • 10k step ≈ Pro 6000 96G 上 3–4 h。RoboCasa 数据 8× 于 LeIsaac，建议 max_steps 起步 15k + 中频 interleave eval。

LoRA rank 纪律：默认 r=4 / alpha=4（~19M，~200 MB/ckpt）。不要像 LLM LoRA 那样开 32/64——视频扩散 LoRA 过 r=16 早期就崩，且 500 demo 过拟合风险已高。只有 step 2000 loss 平台才升 r=16。
